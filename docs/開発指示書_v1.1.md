# DTM Utilities 開発指示書 v1.1

Claude Code への開発指示書。本ドキュメントの内容に従って実装を進めること。

---

## 1. プロジェクト概要

- **プロジェクト名**: DTM Utilities（仮。リポジトリ名: `dtm-utilities`）
- **目的**: 音楽制作（DTM）で頻繁に必要になる計算・参照作業を1つのWebアプリに集約する
- **形態**: クライアントサイド完結のSPA（バックエンド・DB不要）
- **公開先**: GitHub Pages

## 2. 技術構成

| 項目 | 採用技術 |
|---|---|
| ビルド | Vite（最新安定版） |
| フレームワーク | React + TypeScript（strict mode） |
| スタイリング | CSS Modules（外部UIライブラリは使用しない） |
| テスト | Vitest + React Testing Library（テスト工程は後続フェーズで別指示書を提供予定。ただし計算ロジックのユニットテストは実装時に併せて作成すること） |
| Lint / Format | ESLint + Prettier |
| デプロイ | GitHub Pages（`vite.config.ts` の `base` をリポジトリ名に設定、GitHub Actions で自動デプロイ） |

### 設計方針

- 計算ロジックは React から分離した純関数として `src/lib/` に置くこと（テスト容易性のため）
- 各機能は独立したコンポーネントとし、機能間の依存を作らないこと
- 状態管理ライブラリは導入しない（useState / useReducer で足りる規模）

## 3. UI 要件

- タブ切替で5機能を行き来するシングルページ構成
- **ダークテーマを基調**とする（DAW風の配色。DTMユーザーが夜間・暗所で使う想定）
- レスポンシブ対応（スマホでスタジオ外から参照するケースを想定、最小 375px）
- 入力は即時反映（計算ボタンは設けず、入力変更でリアルタイム更新）
- 日本語UI

## 4. 機能仕様

### 機能① ディレイ/リバーブタイム計算機（優先度: 最高）

**入力**:
- BPM（数値、20〜999、デフォルト 120）※BPM は4分音符基準とする（Studio One 等の DAW 標準に合わせる）
- 拍子（分子・分母それぞれ 1, 2, 4, 8, 16, 32, 64 の2の冪乗から選択、デフォルト 4/4）

**出力1: ディレイタイム表**
以下の音価それぞれについて「ノーマル / 付点 / 3連」の ms 値と LFOレート換算の Hz 値を表形式で表示する。

- 対象音価: 1/1, 1/2, 1/4, 1/8, 1/16, 1/32, 1/64
- 計算式:
  - ノーマル: `ms = (60000 / BPM) × (4 / 分母)` ※1/4 = 60000/BPM
  - 付点: ノーマル × 1.5
  - 3連: ノーマル × 2/3
  - Hz: `1000 / ms`
- ms は小数第1位、Hz は小数第2位まで表示
- 各セルはクリックで ms 値をクリップボードにコピーできること

**出力2: リバーブ目安値**
BPM連動のプリディレイ/ディケイ目安を表示する。

| 用途 | プリディレイ | ディケイ |
|---|---|---|
| Tight (Room) | 1/64 相当 ms | 1小節 × 0.25 |
| Medium (Plate/Room) | 1/32 相当 ms | 1小節 × 0.5 |
| Large (Hall) | 1/16 相当 ms | 1小節 × 1.0 |

※1小節 = `(60000 / BPM) × (4 / 拍子分母) × 拍子分子`（例: 4/4 なら 60000/BPM × 4、2/2 なら同値、4/8 なら半分）

### 機能② BPMタップ測定（優先度: 高）

- 画面上の大きなタップ領域（またはスペースキー）を叩いた間隔から BPM を算出
- 直近8回のタップ間隔の平均から算出。2000ms 以上間隔が空いたら計測をリセット
- 表示: 現在のBPM（小数第1位）、タップ回数、リセットボタン
- 算出したBPMを機能①へワンタップで引き継げる導線を設けること

### 機能③ 周波数⇔ノート変換（優先度: 中）

- 双方向変換: 周波数(Hz) → 最寄りのノート名+セント偏差 / ノート名 → 周波数
- 基準ピッチ: A4 = 440Hz 固定（設定変更は実装しない）
- 計算式: `f = 440 × 2^((n − 69) / 12)`（n = MIDIノート番号）
- 出力項目: ノート名（例: A4）、MIDIノート番号、周波数、セント偏差（周波数→ノート時のみ）
- 補助表示: C0〜B8 の全ノート対応表（折りたたみ表示）

### 機能④ LUFS/PLR 早見表+簡易計算（優先度: 中）

**早見表**: 主要配信プラットフォームのターゲットラウドネス一覧（静的データ）

| プラットフォーム | ターゲット (LUFS-I) |
|---|---|
| Spotify | -14 |
| Apple Music | -16 |
| YouTube | -14 |
| ニコニコ動画 | -15 |
| CD / クラブ系マスター | -9 〜 -8 |

True Peak 上限はプラットフォームを問わず **-0.1 dBTP**（発注者の制作標準値）として一律表示する。プラットフォーム別の TP 表示は不要。

※上記の数値はプレースホルダを含む。実装時に発注者へ最終値の確認を求めること。

**簡易計算**: Integrated LUFS と True Peak (dBTP) を入力すると PLR（= TP − LUFS）を算出し、目安レンジ（PLR 9〜11 など）との比較コメントを表示する。True Peak 入力欄のデフォルト値は -0.1 とする。

### 機能⑤ ゲインステージング早見表（優先度: 低・最後に実装）

- 楽器・素材カテゴリ別のターゲットレベル一覧（静的データ、検索/フィルタ付き）
- **データの中身は未確定**。実装フェーズ到達時に発注者から別途データ定義を受領すること。それまでは仮データ3行で枠のみ実装してよい
- 表示項目: カテゴリ / ターゲットレベル (dBFS/VU) / 備考

## 5. 開発フェーズ（WBS）

各フェーズの完了条件を満たしてから次へ進むこと。**フェーズ完了ごとに必ず動作可能な状態でコミットする。**

| Phase | 作業内容 | 完了条件 |
|---|---|---|
| 0 | 環境構築: Vite+React+TS 雛形、ESLint/Prettier、Vitest、GitHub Actions（Pages デプロイ）、タブ切替の空シェルUI | `npm run dev` で空タブ5個が表示され、`npm run test` が通り、main への push で Pages に公開される |
| 1 | 機能①実装 + 計算ロジックのユニットテスト | BPM入力で全表が正しく更新され、コピー機能が動作する |
| 2 | 機能②実装 + ①への連携導線 | タップ計測が安定動作し、BPMが①へ引き継がれる |
| 3 | 機能③実装 + ユニットテスト | 双方向変換とセント偏差表示が正しい |
| 4 | 機能④実装（早見表データは発注者へ確認） | 早見表表示と PLR 計算が動作する |
| 5 | 機能⑤枠実装 →（データ受領後）本実装 | 仮データで表とフィルタが動作する |
| 6 | UI磨き込み: 配色統一、レスポンシブ確認、アクセシビリティ最低限（キーボード操作・コントラスト） | 375px〜デスクトップで崩れがない |

## 6. 運用ルール（Claude Code への指示）

1. 1フェーズ = 1つ以上のコミット。コミットメッセージは Conventional Commits（`feat:`, `fix:`, `test:`, `chore:`）
2. 各フェーズ開始前に、そのフェーズの実装計画を短く提示し、発注者の承認を得てから実装すること
3. 仕様に曖昧さや矛盾を見つけた場合は、推測で実装せず必ず質問すること
4. 計算式は本指示書を正とする。変更が必要と判断した場合は根拠とともに提案すること
5. 依存パッケージの追加は都度理由を添えて報告すること（最小限に留める）

## 7. スコープ外（実装しないこと）

- ユーザー認証、データの永続化（localStorage 含め v1 では不要）
- 多言語対応、ライト/ダークテーマ切替（ダーク固定）
- 音声再生・音声解析機能（BPMタップは手動タップのみ）
- 2の冪乗以外の拍子（3/4、6/8 等は v1 では対象外）
